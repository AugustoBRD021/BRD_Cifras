SITE DE CIFRAS - PLANEJAMENTO
=============================

STACK ESCOLHIDA
----------------
- Backend: Java + Spring Boot (API REST)
- Frontend: React (consome a API)
- Objetivo do projeto: aprendizado (não é pra produção/publicação por enquanto)

ESCOPO DA V1 (MVP)
-------------------
- Listar músicas cadastradas
- Abrir uma música e ver a cifra (letra + acordes)
- Buscar música por nome/artista

MELHORIAS FUTURAS (V2 - fora de escopo por enquanto)
------------------------------------------------------
- Transposição de tom
- Login/cadastro de usuário
- Favoritar músicas
- Comentários
- Upload de cifra por usuários
- Novas entidades possíveis: Tonalidade, Dificuldade, Afinação

MODELAGEM DE DADOS
-------------------
Entidade: Artista
- nome
- descrição
- relacionamento: um Artista tem várias Músicas (1 para N)
  (obs: essa lista de músicas não é um campo salvo em Artista, é a
  outra ponta do relacionamento - quem guarda a referência é a tabela
  Musica, com uma coluna artista_id)

Entidade: Musica
- título
- data de lançamento
- artista (referência ao Artista dono da música)
- corpo da cifra

FORMATO DO CORPO DA CIFRA
---------------------------
Opção escolhida: B - acordes em uma linha separada, acima da letra

    C          G
    Se você quer saber de mim

Implicações dessa escolha (pontos de atenção pra frente):
- Ao salvar o texto, os espaços usados para alinhar o acorde sobre a
  sílaba certa precisam ser preservados exatamente como digitados
  (não pode haver limpeza automática de espaços).
- Ao exibir na tela, será necessário usar fonte monoespaçada (largura
  fixa), senão o alinhamento quebra.
